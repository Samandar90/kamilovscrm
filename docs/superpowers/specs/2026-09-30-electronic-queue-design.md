# Электронная очередь и ТВ-экран — дизайн

**Дата:** 2026-09-30 · **Статус:** утверждён пользователем · **Ветка:** `feat/electronic-queue`

## Цель

Каждый пришедший пациент получает номер в очереди своего врача. Врач (или регистратура/медсестра за него) вызывает пациентов по номеру, а телевизор в холле показывает очереди кабинетов и объявляет вызов сигналом и голосом на узбекском и русском.

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Нумерация | Свой счётчик у каждого врача на день, необязательная буква врача: `К-05`. К двум врачам — два номера. |
| Порядок вызова | Строго по номеру. «Вызвать следующего» берёт наименьший невызванный номер; любого ждущего можно вызвать вручную. |
| Что на ТВ | Номер + имя в виде «Алишер К.» (переключатель на экран, по умолчанию включён). |
| Звук | Сигнал + голос uz, затем ru. Заранее сгенерированные фразы нейроголосами Microsoft (`uz-UZ-MadinaNeural`, `ru-RU-SvetlanaNeural`). |
| Подход | Очередь — поля записи на приём (appointments); статусы записи — единственный источник правды. ТВ опрашивает сервер каждые 2 с. |

Отклонены: отдельная подсистема талонов со своим автоматом состояний (рассинхрон с записями, вдвое больше кода); push через SSE/WebSocket (хрупко на ТВ-браузерах и при рестартах Render, выигрыш 1–2 с незаметен).

## Жизненный цикл

«Сегодня» — календарный день в `env.reportsTimezone` (Asia/Tashkent).

| Состояние в очереди | Условие (запись с номером на сегодня) |
|---|---|
| Ждёт | `status = 'arrived'`, `queue_called_at IS NULL` |
| Вызван | `status = 'arrived'`, `queue_called_at IS NOT NULL` |
| На приёме | `status = 'in_consultation'` |
| Вне очереди | `completed`, `cancelled`, `no_show`, удалённые |

1. **Выдача номера.** Переход записи в `arrived` в одной транзакции выдаёт номер из счётчика врача на сегодня — только если дата записи (`start_at` в TZ клиники) сегодня. Для записей на другой день переход проходит как раньше, без номера (задним числом закрывать визиты можно). Повторная выдача идемпотентна: если номер на сегодня уже есть, возвращается он.
2. **Вызов.** «Вызвать следующего» (`call-next`) выбирает у врача наименьший номер среди «Ждёт» (`FOR UPDATE SKIP LOCKED` — два одновременных нажатия не вызовут одного пациента дважды), ставит `queue_called_at = now()`, `queue_call_count = 1`. «Вызвать» конкретного (ждёт или вызван) — `queue_called_at = now()`, `queue_call_count += 1`; это же «Повторить вызов».
3. **Начать приём / Завершить** — существующие переходы в `in_consultation` / `completed`.
4. **Не пришёл** — существующий переход в `no_show`. Новый разрешённый переход `no_show → arrived` (только для записи на сегодня): пациент вернулся — получает **новый** номер в конце очереди.
5. **Смена врача** у записи с номером: если запись на сегодня и в статусе `arrived` — новый номер из счётчика нового врача, вызов сброшен; иначе поля очереди очищаются. **Перенос на другой день** — поля очереди очищаются. Всё в той же транзакции, что и изменение записи.
6. Записи, ушедшие в `in_consultation` без номера (врач принял напрямую), в очереди не нумеруются; на ТВ показываются как «На приёме» без номера.

Номера в течение дня не переиспользуются (отменённая запись не освобождает номер).

**Код талона:** `${prefix}-${NN}` при наличии буквы, иначе `NN`; `NN` — номер, дополненный нулём до двух цифр (`К-05`, `К-123`, `07`).

## Данные — миграция `035_electronic_queue.sql` (только добавления)

```sql
ALTER TABLE doctors
  ADD COLUMN IF NOT EXISTS room TEXT NULL
    CHECK (room IS NULL OR char_length(btrim(room)) BETWEEN 1 AND 20),
  ADD COLUMN IF NOT EXISTS queue_prefix TEXT NULL
    CHECK (queue_prefix IS NULL OR char_length(queue_prefix) = 1);

ALTER TABLE appointments
  ADD COLUMN IF NOT EXISTS queue_number INTEGER NULL CHECK (queue_number > 0),
  ADD COLUMN IF NOT EXISTS queue_date DATE NULL,
  ADD COLUMN IF NOT EXISTS queue_issued_at TIMESTAMPTZ NULL,
  ADD COLUMN IF NOT EXISTS queue_called_at TIMESTAMPTZ NULL,
  ADD COLUMN IF NOT EXISTS queue_call_count INTEGER NOT NULL DEFAULT 0;

-- Страховка от дублей поверх счётчика.
CREATE UNIQUE INDEX IF NOT EXISTS ux_appointments_queue_ticket
  ON appointments (doctor_id, queue_date, queue_number)
  WHERE queue_number IS NOT NULL;
-- Очередь клиники на день (ТВ и страница «Очередь»).
CREATE INDEX IF NOT EXISTS idx_appointments_queue_day
  ON appointments (clinic_id, queue_date, doctor_id)
  WHERE queue_number IS NOT NULL AND deleted_at IS NULL;

-- Атомарный счётчик: INSERT ... ON CONFLICT DO UPDATE SET last_number = last_number + 1 RETURNING.
CREATE TABLE IF NOT EXISTS queue_counters (
  clinic_id BIGINT NOT NULL,
  doctor_id BIGINT NOT NULL REFERENCES doctors(id),
  queue_date DATE NOT NULL,
  last_number INTEGER NOT NULL CHECK (last_number > 0),
  PRIMARY KEY (doctor_id, queue_date)
);

CREATE TABLE IF NOT EXISTS queue_displays (
  id BIGSERIAL PRIMARY KEY,
  clinic_id BIGINT NOT NULL REFERENCES clinics(id),
  name TEXT NOT NULL CHECK (char_length(btrim(name)) BETWEEN 1 AND 100),
  token_hash TEXT NOT NULL UNIQUE,            -- sha256(hex) кода экрана; сам код не хранится
  doctor_ids BIGINT[] NULL,                   -- NULL = все врачи, у кого сегодня есть очередь
  show_names BOOLEAN NOT NULL DEFAULT TRUE,
  language TEXT NOT NULL DEFAULT 'uz_ru' CHECK (language IN ('uz', 'ru', 'uz_ru')),
  voice_enabled BOOLEAN NOT NULL DEFAULT TRUE,
  created_by BIGINT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  revoked_at TIMESTAMPTZ NULL
);
CREATE INDEX IF NOT EXISTS idx_queue_displays_clinic
  ON queue_displays (clinic_id) WHERE revoked_at IS NULL;
```

`appointments.clinic_id` и `doctors.clinic_id` в production есть (дрейф схемы вне миграций) — миграция на них опирается.

**Код экрана** — 10 символов из алфавита без похожих знаков (`23456789ABCDEFGHJKMNPQRSTUVWXYZ`), показывается как `XXXXX-XXXXX`, ≈49 бит. Короткий, чтобы набрать пультом. Хранится только хеш; код показывается при создании и при «Новый код» (старый перестаёт работать). Один телевизор — один экран.

## API

### Сотрудники — `/api/queue` (requireAuth → контекст клиники → подписка → `checkPermission("queue", …)`)

| Метод | Путь | Право | Назначение |
|---|---|---|---|
| GET | `/today?doctorId=` | read | Очереди врачей на сегодня: на приёме, вызванные, ждущие (id записи, код, полное ФИО, время записи, `issuedAt`, `calledAt`, `callCount`), счётчик принятых |
| POST | `/appointments/:id/issue` | create | Выдать номер записи в `arrived` без номера (идемпотентно) |
| POST | `/appointments/:id/call` | update | Вызвать / повторить вызов |
| POST | `/doctors/:doctorId/call-next` | update | Вызвать следующего; `{ entry: null }`, если ждущих нет |
| GET | `/appointments/:id/ticket` | read | Данные талона: клиника, код, врач, специальность, кабинет, `issuedAt`, `aheadCount` |
| GET/POST | `/displays` | superadmin | Список / создать экран (ответ создания содержит код один раз) |
| PATCH/DELETE | `/displays/:id` | superadmin | Изменить / удалить (`revoked_at`) |
| POST | `/displays/:id/rotate-code` | superadmin | Новый код экрана |

Выдача номера при `arrived`, «Не пришёл», «Начать приём», «Завершить» идут через существующий эндпоинт статуса записи.

**Область врача:** роль `doctor` видит и вызывает только свою очередь (`auth.doctorId`), `nurse` — очередь своего врача (`nurseDoctorId`), как в `clinicalDataScope`. Чужой `doctorId` → 403.

### Публичный — ТВ

`GET /api/public/queue-display/:code` — без авторизации, rate limit 300 запросов/мин на IP, ответ `Cache-Control: no-store`.

- Код неизвестен или экран удалён → 404 → ТВ: «Экран отключён. Попросите администратора выдать новый код.»
- Подписка клиники неактивна → 403 → ТВ: «Подписка клиники неактивна.»

```ts
type QueueDisplayState = {
  serverTime: string;                       // ISO; ТВ выравнивает часы и «свежесть» вызовов по нему
  clinicName: string;
  display: { name: string; language: "uz" | "ru" | "uz_ru"; voiceEnabled: boolean; showNames: boolean };
  cabinets: Array<{
    doctorId: number; doctorName: string; specialty: string; room: string | null;
    current: null | { code: string | null; name: string | null; state: "called" | "serving" };
    waiting: Array<{ code: string; name: string | null }>; // первые 5 «Ждёт»
    waitingCount: number;
  }>;
  recentCalls: Array<{                      // последние 20 вызовов сегодня, новые первыми
    key: string;                            // `${appointmentId}:${callCount}`
    code: string; number: number; name: string | null;
    room: string | null; doctorName: string; calledAt: string;
  }>;
};
```

- `current`: пациент «На приёме» (если таких несколько — последний по `updated_at`), а если такого нет — последний вызванный.
- Кабинеты: если `doctor_ids` задан — эти врачи всегда (пустые с «Очереди нет»); иначе — врачи с очередью сегодня. Сортировка по кабинету (числовые по возрастанию, затем остальные), затем по ФИО врача.
- **Имя** (`showNames`): ФИО хранится как «Фамилия Имя Отчество» → «Имя Ф.»; одно слово → как есть. Маскирование на сервере — полное ФИО в публичный ответ не попадает никогда. `showNames = false` → `name: null`.
- Только сегодняшние данные клиники экрана; телефонов, id пациентов, услуг и сумм в ответе нет.

## Права (RBAC)

Новый модуль `queue` в `services/api/src/auth/permissions.ts` и зеркально в `apps/web/src/auth/permissions.ts`:

| Роль | queue |
|---|---|
| reception | read, create, update |
| doctor | read, update (только своя очередь) |
| nurse | read, update (очередь своего врача) |
| manager, director | read |
| superadmin | всё + управление экранами |

## Интерфейс (apps/web, ru + uz, `check-i18n` проходит)

- **Страница «Очередь»** `/queue` (пункт меню). Обновление каждые 5 с.
  - Врач: карточка текущего пациента (Начать приём / Не пришёл / Повторить вызов), крупная кнопка «Вызвать следующего · К-06», список ждущих (код, ФИО, время записи, ждёт N мин, «Вызвать»).
  - Регистратура/медсестра: колонки по кабинетам с теми же действиями; менеджер/директор — только просмотр.
  - Суперадмин: кнопка «Экраны» → список экранов, создание (название, врачи, имена вкл/выкл, язык, голос вкл/выкл), показ кода и ссылки, «Новый код», удаление, «Открыть экран».
- **Записи.** Код очереди на карточке записи. После «Пришёл» — уведомление «Выдан номер К-05» с кнопкой «Печать талона»; кнопка «Талон» у записи с номером.
- **Талон** — печать через скрытый iframe и `window.print()`, ширина 58 мм (подходит и для 80 мм): клиника, «Navbat raqami / Номер очереди», крупный код, врач и специальность, «Xona / Кабинет», дата и время, «Oldingizda / Перед вами: N».
- **Карточка врача.** Поля «Кабинет» (до 20 символов) и «Буква очереди» (одна буква, необязательно, приводится к верхнему регистру).
- **ТВ-экран** — публичные маршруты вне авторизованного layout: `/tv` (поле ввода кода → переход) и `/tv/:code`.
  - Тёмная контрастная тема, размеры от ширины экрана (720p–4K). Шапка: клиника, «Navbat / Очередь», часы по серверному времени.
  - Сетка карточек кабинетов (как на утверждённом макете); при нехватке места — страницы по 10 с.
  - Лента «Последние вызовы».
  - Окно вызова поверх экрана на 10 с: код, имя, «→ Xona / Кабинет N». Несколько вызовов — по очереди.
  - Старт: кнопка «Ekranni ishga tushirish / Запустить экран» (разблокирует звук, полноэкранный режим, Wake Lock).
  - Опрос каждые 2 с; после 3 неудач — плашка «Нет связи», последние данные остаются, повтор с паузой до 10 с.
  - Ежедневная перезагрузка страницы в 04:00 (новые версии, очистка памяти).
  - Надписи по `display.language`: `uz_ru` — обе строки, иначе одна.
- **Обнаружение вызова на ТВ:** ключи `recentCalls[].key`, увиденные при первой загрузке, считаются старыми; новый ключ с `calledAt` не старше 2 минут по `serverTime` → в очередь объявлений (по возрастанию `calledAt`). Повторный вызов даёт новый ключ (`callCount` вырос) → объявляется снова.

## Голос

- Сигнал «динь-дон» синтезируется Web Audio — без файла.
- Фразы собираются из клипов `apps/web/public/queue-voice/{uz,ru}/<id>.mp3`, воспроизведение через Web Audio (клипы декодируются заранее и ставятся встык):
  - ru: `nomer` + число + `proydite_v_kabinet_nomer` + число кабинета → «Номер двадцать семь. Пройдите в кабинет номер пять.»
  - uz: `navbat_raqami` + число + число кабинета + `raqamli_xonaga_kiring` → «Navbat raqami yigirma yetti. Besh raqamli xonaga kiring.»
  - Кабинет не число 1–999 или не задан: ru `nomer` + число + `vas_priglashayut`; uz `navbat_raqami` + число + `qabulga_marhamat`.
  - Номер > 999: число не озвучивается, звучит только сигнал.
  - Буква очереди не озвучивается — кабинет однозначно определяет очередь.
  - Порядок: `uz_ru` — узбекская фраза, затем русская; `uz` / `ru` — одна.
- **Числа 1–999:**
  - ru: 1–19, десятки 20–90, сотни 100–900 — 36 клипов.
  - uz: 1–9, десятки 10–90, сотни `yuz` … `to'qqiz yuz` — 27 клипов.
  - Плюс служебные фразы. Всего ≈ 70 файлов, ≈ 1 МБ.
- **Генерация** — разовый скрипт `apps/web/scripts/generate-queue-voice.mjs`: Azure Speech REST (SSML, `audio-24khz-48kbitrate-mono-mp3`), ключ и регион из `AZURE_SPEECH_KEY` / `AZURE_SPEECH_REGION` (только локально, не коммитится). Готовые mp3 коммитятся; в работе ключ не нужен. Клипы можно заменить живой записью без изменения кода.
- **Пока клипов нет**, экран работает только с сигналом.
- **Зависимость:** пользователь создаёт бесплатный ресурс Azure Speech (F0) и даёт ключ на время генерации.

## Ошибки и граничные случаи

- Две вкладки одновременно «Вызвать следующего» → `SKIP LOCKED`: вызываются разные пациенты, либо второй получает `null`.
- Две одновременные выдачи номера у одного врача → атомарный upsert счётчика плюс уникальный индекс.
- Запись удалили после вызова → исчезает из очереди и с ТВ.
- Полночь: очередь нового дня пуста; вчерашние «Ждёт» в сегодняшнюю очередь не попадают.
- Врач без кабинета → на ТВ «Кабинет —», голос по запасной фразе; в настройках экрана предупреждение «У врача не указан кабинет».
- Экран без врачей с очередью → «Очереди пока нет».

## Не входит в этап (YAGNI)

Терминал самостоятельной выдачи номеров, очередь в кассу и лабораторию, SMS с номером, статистика ожидания (данные — время выдачи и вызова — копятся уже сейчас), приоритет по времени записи.

## Проверка

- **API** — vitest + PGlite по образцу `PostgresQuestionnairesRepository.test.ts`, через HTTP-роутер:
  - номера 1, 2, 3 по врачу; врачи независимы; новый день с 1;
  - выдача только на сегодня и идемпотентна; `arrived` для записи на другой день проходит без номера;
  - `call-next` — наименьший «Ждёт», пропускает вызванных, на приёме и выбывших; пустая очередь → `null`;
  - врач не вызывает чужую очередь, медсестра — только своего врача;
  - смена врача → новый номер, перенос на другой день → очистка;
  - `no_show → arrived` → новый номер в конце;
  - публичный эндпоинт: хеш кода, удалённый экран → 404, маскирование имени, `showNames = false`, фильтр врачей, только сегодня, без лишних полей.
- **Web** — vitest: сборка фраз uz/ru (1, 5, 11, 20, 27, 100, 115, 999, кабинет не число, номер > 999); детектор вызовов (первая загрузка молчит, новый ключ объявляется, повторный вызов объявляется, старые > 2 мин игнорируются); формат кода талона.
- **Вручную** — одноразовый локальный стенд на PGlite по образцу `services/api/scripts/call-center-preview.cjs` (без production API и БД): выдача, вызов, ТВ-экран, печать талона. Скриншоты ТВ-экрана.
- `npm run typecheck`, `npm test` (api и web), `npm run build` (web) — зелёные.

## Развёртывание

Миграция применяется автоматически при старте сервиса на Render (`db-migrate.cjs`). Изменения только добавляют. Для существующих сценариев меняются две вещи: «Пришёл» у записи на сегодня теперь выдаёт номер, и появился переход «Не явился → Пришёл» для записей на сегодня.

**Оборудование:** любой ТВ с современным браузером; надёжнее Android TV-приставка или мини-ПК с Chrome по HDMI. Талоны — любой чековый принтер 58/80 мм, установленный в Windows.
