# Лиды и аккаунт таргетолога

Лиды из Google-таблицы таргетолога сами попадают в CRM. Сотрудники клиники работают с ними в разделе «Лиды», таргетолог видит только свои лиды и что с каждым стало. Дизайн и причины решений: `docs/superpowers/specs/2026-10-03-marketer-leads-design.md`.

## Кто что видит

| Роль | Что доступно |
|---|---|
| Владелец (superadmin) | Раздел «Лиды» целиком и блок «Источники»: источники, привязка таргетолога, подключение таблицы. |
| Регистратура, оператор, менеджер | Раздел «Лиды»: список, статус, заметка, пациент, запись на приём. |
| Таргетолог | Одна страница «Мои лиды»: дата, имя, телефон, источник, статус. Больше ничего в CRM. |
| Директор, врач, медсестра, кассир, бухгалтер | Раздела нет. |

Таргетолог не видит заметки сотрудников, кто работал с лидом, остальные колонки таблицы, пациента и запись. Статусы «Записан» и «Пришёл» он видит.

## Как подключить таргетолога (владелец, один раз)

1. **«Пользователи» → «Добавить».** Роль «Таргетолог». Аккаунт создаётся новый; переводить в эту роль аккаунт сотрудника нельзя: его прежний вход действует до 8 часов.
2. **Таблица.** В Google-таблице: «Настройки доступа» → «Все, у кого есть ссылка» → «Читатель». Первая строка — заголовки. Обязательна колонка телефона.
3. **«Лиды» → «Источники» → «Добавить источник».** Название, таргетолог, ссылка на таблицу (обычная ссылка из адресной строки; лист берётся из неё же).
4. **«Проверить таблицу».** CRM покажет, какие заголовки нашла и сколько строк годится. Если колонку телефона не узнала, выберите её из списка и сохраните.
5. **Включить «Читать автоматически».** Дальше CRM читает таблицу каждые 5 минут. «Прочитать сейчас» читает сразу.

Отключить таргетолога: «Пользователи» → выключить аккаунт. Доступ пропадает со следующего запроса. Отвязать его от источника: «Источники» → «Изменить» → «не привязан».

## Какие заголовки узнаёт CRM

Регистр, пробелы, подчёркивания, дефисы, точки и двоеточия не важны.

| Колонка | Заголовки |
|---|---|
| Телефон (обязательно) | Телефон, Номер телефона, Телефонный номер, Тел, Моб, Мобильный, Мобильный телефон, Номер, Phone, Phone number, Mobile, Mobile phone, Tel, Telefon, Telefon raqami, Telefon raqam, Raqam |
| Имя | Имя, ФИО, Имя и фамилия, Клиент, Имя клиента, Полное имя, Name, Full name, First name, Ism, Ism familiya, Ismi, FIO, Mijoz |

- Строка заголовков — первая из первых 10 строк, где есть заголовок телефона. Над ней может быть строка с названием таблицы.
- Остальные непустые колонки (до 40) сохраняются как дополнительные сведения и видны сотрудникам в раскрытой строке лида.
- Строка без пригодного телефона не становится лидом; она считается в «без телефона».
- Телефоны `+998 90 123-45-67`, `998901234567`, `901234567` и `(90) 123 45 67` — один и тот же номер.

## Что считается одним лидом

Один телефон в одном источнике — один лид. Повторная строка с тем же номером новым лидом не станет. CRM только добавляет: правка или удаление строки в таблице в CRM ничего не меняет, поэтому таргетолог не может ни переписать, ни стереть запись клиники. Исправленный в таблице телефон даст второй лид; первый останется.

## Статусы лида

| Статус | Когда |
|---|---|
| Новый | Пришёл из таблицы, никто не трогал. |
| В работе | Сотрудник нажал «Взять в работу» или привязал пациента. |
| Не дозвонились | Позвонили, не ответил. |
| Записан | Поставлен вручную или показан сам: у привязанного пациента есть запись, созданная после лида. |
| Пришёл | Показывается сам: привязанный пациент пришёл на запись, созданную после лида. |
| Отказ | Дозвонились, не интересно. |
| Некачественный | Неверный номер, спам, тест, не целевой. |

Если двое берут один лид одновременно, второй увидит «Лид уже изменил коллега», список обновится.

## Лид → пациент → запись

В раскрытой строке лида: «Найти пациента» показывает до 5 пациентов с тем же номером; «Привязать» связывает лид с пациентом. Если пациента нет — «Создать пациента» (имя и телефон из лида можно поправить). После привязки появляется «Записать на приём». Сам лид пациентом не становится и автоматически ни к кому не привязывается: одним номером пользуются семьи.

## Состояние чтения таблицы

| Код | Что видит владелец | Что делать |
|---|---|---|
| `ok` | Прочитано | — |
| `empty` | В таблице пока нет строк | Ничего: лиды появятся, когда появятся строки. |
| `no_access` | Нет доступа к таблице | Открыть доступ «Все, у кого есть ссылка — Читатель». |
| `not_found` | Таблица или лист не найдены | Проверить ссылку; лист мог быть удалён. |
| `columns_not_found` | Не найдена колонка телефона или имени | «Проверить таблицу» и выбрать колонки. |
| `too_large` | Таблица слишком большая | Больше 5 МБ, 5000 лидов или 20 000 строк: завести новый лист. |
| `timeout` | Google не ответил за 20 секунд | Подождать следующего чтения. |
| `http_error` | Ошибка сети или ответа | Подождать; если повторяется — смотреть логи API. |

Ошибка чтения никогда не читается как «таблица пуста», и уже полученные лиды не трогаются.

## Цена чтения по ссылке

Таблицу может прочитать любой, у кого есть ссылка на неё. CRM эту открытость не увеличивает, но зависит от неё: если доступ по ссылке закрыть, чтение остановится с «Нет доступа». Идентификатор таблицы хранится в базе, виден только владельцу и не пишется в логи. Если таблицу нужно закрыть, понадобится чтение через служебный аккаунт Google (не реализовано).

## Как устроено

- Таблицы `lead_sources` и `leads` (миграция `038_leads.sql`); роль `marketer` (миграция `037_users_role_marketer.sql`).
- API: `services/api/src/routes/leadsRoutes.ts`, `services/leadsService.ts`, `services/leads/*`, `repositories/postgres/PostgresLeadsRepository.ts`.
- Чтение: `https://docs.google.com/spreadsheets/d/<id>/export?format=csv&gid=<gid>`. Адрес строит сервер; перенаправления разрешены только на `docs.google.com` и `*.googleusercontent.com`.
- Расписание: в процессе API, первое чтение через 60 секунд после старта, затем каждые 5 минут. Выключается переменной `LEADS_SHEET_SYNC_ENABLED=false`. В логе одна строка на цикл, только числа и коды.
- Веб: `apps/web/src/modules/leads` — страницы `/leads` и `/my-leads`.
- У таргетолога пустая строка прав. Ему открыт один адрес с данными, `GET /api/leads/mine`; тест `marketerAccess.test.ts` обходит все адреса API с его токеном и ждёт 403 везде, кроме явного списка.
- Отключённый, удалённый или сменивший роль аккаунт таргетолога теряет доступ на следующем запросе: для внешних ролей `requireAuth` сверяется с базой.

## Локальная проверка

Только на стенде, никогда на production (`apps/web/.env` указывает на рабочий API):

```bash
node services/api/scripts/queue-preview.cjs --smoke
```

```bash
node services/api/scripts/queue-preview.cjs
```

Веб стенда запускается так же, как для очереди (`docs/queue.md`, «Локальная проверка»). Аккаунты стенда с лидами: `admin`, `reception`, `operator`, `manager`, `marketer`, `marketer2`, пароль `preview`. Источник «Реклама Instagram» читает встроенный образец таблицы без сети; любая другая ссылка читается из Google по-настоящему.

## Выкладка и откат

Сначала API (Render применяет миграции 037 и 038 при старте), затем веб (Vercel). Обе миграции только добавляют: 037 в production ничего не меняет, 038 создаёт две новые таблицы. Откат — выкладка предыдущих сборок; таблицы остаются и не мешают.
