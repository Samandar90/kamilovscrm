# Колл-центр: работа и выпуск

## Что изменилось

База всех активных пациентов клиники доступна без правил напоминаний. Для каждого пациента показываются последний завершённый визит, следующая активная запись и история контактов. Кампании: возврат давно не приходивших пациентов без следующей записи, обратная связь после визита, напоминания перед предстоящим приёмом. Перезвоны хранятся отдельно и не исчезают при изменении правил.

Суперадминистратор задаёт сроки, включает кампании, меняет рабочие часы, интервалы и число попыток, сценарий разговора; предварительная выборка не сохраняет настройки. Оператор берёт пациента в работу на 10 минут, звонит со своего телефона, сохраняет исход и заметку. «Не дозвонились» автоматически назначает повтор в рабочее время. «Перезвонить» требует будущую дату. Каждая попытка сохраняется отдельно; старый журнал напоминаний также доступен.

Кнопка записи открывает существующую форму записи с выбранным пациентом. Перенос и отмена выполняются в расписании: исход звонка сам по себе запись не меняет. Оператор может создавать записи по ценам каталога, но не получает доступ к финансам и настройкам.

## Проверка локально

В API добавлены интеграционные тесты с реальными SQL-запросами в изолированной PGlite, проверки доступа, повторных отправок и конфликтов операторов. Интерфейс содержит проверки восстановления после HTTP-ошибок, сохранности заметок и работы с датами.

```powershell
npm test --prefix services/api
npm run typecheck --prefix services/api
npm test --prefix apps/web
npm run typecheck --prefix apps/web
npm run build --prefix apps/web
```

Локальный стенд с вымышленными пациентами, без `.env` и подключений к рабочей БД:

```powershell
node services/api/scripts/call-center-preview.cjs
# В другом терминале:
$env:VITE_API_URL='http://127.0.0.1:4400'
npm run dev --prefix apps/web -- --host 127.0.0.1 --port 5175
```

Открыть `/call-center`; тестовые логины `admin`, `operator`, `operator2`, пароль `preview`. Данные стенда исчезают после остановки процесса. Другие разделы CRM на этом стенде не реализованы. Это средство проверки, не замена рабочего API.

## Условия выпуска

Рабочий сайт в рамках разработки не обновлялся. Перед публикацией:

1. Проверить резервную копию БД и существующую историю миграций. В старой цепочке проекта отсутствуют базовые миграции многоклиничности — не запускать её вслепую на рабочей БД.
2. Убедиться, что существуют `clinics`, `patients.clinic_id`, `appointments.clinic_id`, `doctors.clinic_id`, `users.clinic_id`, а также миграция 031. Применить аддитивную миграцию `032_call_center_workspace.sql` через согласованный процесс миграций и зарегистрировать её в `schema_migrations`.
3. Выпустить API, затем интерфейс. Проверить вход суперадминистратора и оператора, выборку существующих пациентов, сохранение настроек и тестовый перезвон. Не выполнять реальные звонки при проверке.

Новые таблицы не удаляют старые данные. Старые маршруты правил и отметок напоминаний сохранены. Работа нового модуля требует PostgreSQL; обычный DATA_PROVIDER=mock намеренно не изображает долговременное хранение и отвечает 503. Для демонстрации используется отдельный стенд выше.

## Ограничения

Нет интеграции с телефонией, записи разговоров или автоматической отправки сообщений. Интерфейс времени настроен на Ташкент (UTC+5), как текущая клиника; сервер использует REPORTS_TIMEZONE. При изменении часового пояса требуется согласовать интерфейс.

Проверка зависимостей выявила старые предупреждения безопасности. В веб-lockfile применены совместимые исправления без смены основных версий; остаются предупреждения React Router 6, переход на другую основную версию не входит в эту доработку. Предупреждение размера основного JS-пакета также существовало до изменений; новый колл-центр загружается отдельно по маршруту.
