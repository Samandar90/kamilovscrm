## Сделано
- Скрипт миграций не пишет в лог значения из строк базы (03.10.2026, PR #18, в него входят PR #14 и PR #10). `services/api/scripts/db-migrate.cjs` выполняется при каждом старте на Render и при сбое миграции печатал ошибку PostgreSQL целиком, с `detail` (`Key (clinic_id, phone)=(1, +998…) is duplicated.`, `Failing row contains (…)`). Теперь он печатает строку `[fail] <файл>`, код SQLSTATE, ограничение, таблицу, колонку, функцию PostgreSQL и стек; текст ошибки остаётся только у класса 42 (ошибка в самой миграции, в тексте имена объектов схемы) и у ошибок не от PostgreSQL. Код выхода прежний: 1. Правило то же, что в `errorForLog`, и повторено в самом скрипте: `dist/utils/logRedaction.js` не загружается без `JWT_SECRET` (тянет `config/env`), а `npm run db:migrate` запускают и без сборки. Тест `src/scripts/dbMigrate.test.ts` запускает скрипт на PGlite и сверяет его вывод с `errorForLog`.
- ТВ называет врача (03.10.2026): «Номер 27. Пройдите к врачу Каримову Дилшоду Рустамовичу.» Номер читают клипы, ФИО в дательном падеже (`lvovich`, `doctorSpeech.ts`) читает русский голос браузера ТВ (`speechVoice.ts`); кабинет больше не озвучивается. Без русского голоса в браузере ТВ: «Номер 27. Пройдите на приём.» Проверено на движке речи Windows (Microsoft Irina). После слияния на своём ПК выполнить `npm install` в `apps/web` (новая зависимость `lvovich`).
- Скорость сайта (03.10.2026, PR #15): список записей больше не скачивается целиком. «Записи» одним запросом берут сегодня и 7 дней вперёд, поэтому «Сегодня», «Завтра» и «Неделя» переключаются без запросов; дата в календаре вне этого окна запрашивается отдельно. «Панель управления» берёт только сегодня, рабочее место врача — одну запись по id. Подсказки свободного времени при занятом слоте запрашивают записи этого врача за этот день. Если запрос периода не прошёл, страница пишет «Ошибка загрузки» с кнопкой «Повторить», а не «Нет записей».
- API к тому же PR: фильтр `startFrom`/`startTo` у `GET /api/appointments` уже был, теперь он закреплён тестами. Добавлены параметр `limit` и миграция 036: индекс `appointments(clinic_id, start_at)`, применится сама при старте API.
- Личные данные и текст пользователей не пишутся в лог через `console.*` (03.10.2026, PR #14, в него входит и PR #10). ИИ-ассистент пишет длину сообщения, роль и вердикт вместо текста (`[AI V2] ask`, `[AI] ask intent`, `[AI] patient_search query`, `PROMPT:`), вместо ответа OpenAI — его длину и число токенов (`AI RESPONSE:`). Ошибки PostgreSQL пишутся без `detail`, `where` и текста со значениями полей: остаются код, ограничение, таблица, колонка и стек (`RAW BACKEND ERROR:` и 25 блоков `catch`). Всё идёт через `services/api/src/utils/logRedaction.ts`.
- Текст поиска не пишется в лог запросов API (03.10.2026, PR #10): в строке лога значение `search` заменено на `***` (`GET /api/patients?search=***`), путь и остальные параметры остаются. Параметр закрыт на всех маршрутах, где в нём свободный текст: `/api/patients`, `/api/users`, `/api/questionnaires`, `/api/call-center/workspace` (`requestLogger.ts`).
- Надписи на ТВ только по-русски (03.10.2026): `TV_TEXT_LANGUAGE = "ru"` в `tvLabels.ts`, заголовок вкладки и экран сбоя тоже русские. Настройка «Язык надписей и голоса» в форме экрана теперь ни на что не влияет (можно убрать из формы).
- ТВ говорит только по-русски (03.10.2026, PR #9): `voiceLangs()` всегда `["ru"]`, узбекские клипы остаются в репозитории, но не грузятся и не звучат. Надписи на экране по-прежнему зависят от языка экрана.
- Скорость сайта (03.10.2026). Страница «Записи» запрашивала счёт отдельно для каждой записи клиники за всё время: около 750 записей, примерно 1500 запросов и 11 секунд на каждое открытие и после каждого действия. Теперь счета приходят одним запросом (`appointmentsPageData.ts`, PR #7).
- API разрешает браузеру кешировать CORS-preflight на сутки (`corsOptions.ts`). Раньше почти каждый запрос к API стоил двух обращений к серверу.
- API держит 8 подключений к базе открытыми (`services/api/src/config/database.ts`, `min: 8`). Раньше pg закрывал их через 10 секунд простоя, и страница, открытая после паузы, ждала новые подключения: пять запросов списков отвечали за 130–570 мс вместо 20–100 мс. Добавлен обработчик ошибок пула: без него обрыв простаивающего подключения остановил бы процесс.
- Запросы без ответа больше не висят вечно (`apps/web/src/api/http.ts`). Чтение (GET) ждёт 5, 10 и 20 секунд и повторяется само. Запись отправляется один раз с лимитом 60 секунд. AI-чтения помечены `slow`: одна попытка, 60 секунд. Это закрывает и зависание опроса на странице «Очередь».
- Электронная очередь в production с 01.10.2026 (PR #3, миграция 035). Голос ТВ: 69 клипов OpenAI `gpt-4o-mini-tts` (PR #4). На ТВ в «Далее» видны имена ожидающих (PR #6).

Стек начинается с текста ошибки, а PostgreSQL цитирует в нём значение целиком: если значение в несколько строк и одна из них начинается с `at`, она попадёт в лог (в тесте скрипта миграций так вышла строка `at 18:00 жене, 901112233"`). В `db-migrate.cjs` кадры берутся только из того, что идёт после текста ошибки; сделать так же в `errorForLog`.

## Заметки
- Зависший запрос 03.10.2026 в 10:33: поиск пациента висел в браузере больше 5 минут и до API не дошёл. Браузер ходит к API по HTTP/3 (QUIC). Два замера по 4 минуты с этого ПК (HTTP/2 и HTTP/3) прошли без единого сбоя, то есть сбой эпизодический. Если зависания повторятся, проверить с выключенным QUIC в Chrome (`chrome://flags/#enable-quic`).
- Как искали причину медленной работы: логи и метрики Render (сервер и база простаивают, CPU около 1%), замеры с этого ПК: до сервера около 100 мс на запрос, потери пакетов 1–2%, Cloudflare отвечает из Варшавы.
- Локально проверять только на стенде (`VITE_API_URL=http://127.0.0.1:4401`): `apps/web/.env` указывает на production. Счета на стенде очереди не реализованы. Если порт 4401 занят стендом другого чата, запустить временную копию `queue-preview.cjs` с другим портом и направить на неё `VITE_API_URL`; копию не коммитить.
- Тесты API больше не требуют `services/api/.env`: `npm test` проходит и в свежем worktree.
- Ключи OpenAI и Azure не печатать и не коммитить. Клипы OpenAI генерируются с `--env-file=../../services/api/.env`; ключ Azure — только в переменных текущего окна терминала.
- ТВ: Chromium ≥ 87; надёжнее мини-ПК с Chrome в режиме киоска (`--kiosk --autoplay-policy=no-user-gesture-required`).
- Коммит в `main` выкладывает web (Vercel); API (Render, корень `services/api`) перевыкладывается только при изменениях в `services/api`.
- В логе API нет текста сообщений ИИ и значений из базы. Для локальной отладки: `DEBUG_AI_TEXT=1` (текст сообщений, промптов и ответов) и `DEBUG_ERROR_DETAILS=1` (ошибка целиком, с `detail`; действует и на `npm run db:migrate`); в production оба флага не включаются (`config/env.ts`, для миграций — в самом `db-migrate.cjs`). Суммы выручки ИИ-ассистента (`[AI FACTS] revenueToday…`) в логе остались: это не личные данные.
